# JumpCloud Login Assistant 0.3.0 구현·검증 기록

**목표:** 잠금 암호 기능을 제거하고 Tampermonkey에 등록한 ID/PW로 자동 로그인한다. 실제 자격증명은 소스·Git에 넣지 않으며 GM에는 평문으로 보관한다. 저장 데이터 유출 시 원문 노출 위험이 있음을 UI와 문서에 명시한다.

**설계:** [보안·동작 설계](jumpcloud-login-design.md). JavaScript userscript, GM API, Web Locks, 전용 제출 시각 저장소. MFA는 직접 완료하며 암호화·키 관리 기능은 제거한다.

**환경:** Node.js `^22.22.2 || ^24.15.0 || >=26.0.0`, jsdom 30.0.1, 신규 의존성 없음. 작업 시작 커밋 `190043d`, main과 origin/main 0/0, 작업 트리는 깨끗했다.

## 체크포인트 1: 잠금 없는 자동 로그인

**파일:** `jumpcloud-login-assistant.user.js`, `test/jumpcloud-login-assistant.test.js`.

- [x] 잠금 암호·확인 입력, 잠금 해제 메뉴, PBKDF2/AES-GCM과 키 처리 코드를 제거한다.
- [x] 설정 창을 이메일·비밀번호 두 필드와 **저장 후 자동 로그인** 버튼으로 바꾼다.
- [x] GM `credentials: {email, password}` 저장과 새 페이지의 자동 입력을 연결한다.
- [x] 저장 시 자동 진행을 먼저 끄고 모든 설정 작업이 끝난 후에만 켠다.
- [x] 이전 `vault`는 자동 삭제·복호화하지 않고 재등록을 안내한다. 새 값 저장이 성공한 뒤 이전 암호문을 삭제한다.
- [x] 부적합·이전 저장 정보가 있으면 외부 자동완성으로 우회하지 않는다.
- [x] 계정 일치, 기존 입력 보호, 중지·숨김 시 미제출 비밀번호 정리와 수동 제출 보존을 유지한다.
- [x] 신규 동작의 실패 테스트를 먼저 확인하고 구현 후 전체 회귀를 통과시킨다.
- [x] diff와 실제 자격증명 유입 여부, 테스트·문법·공백 검사를 확인한다.
- [x] `b4f6073 feat(jumpcloud)!: remove vault passphrase requirement`로 커밋·일반 push하고 upstream 0/0을 확인한다.

## 검증 증거

| 검사 | 결과 |
| --- | --- |
| JumpCloud 테스트 | 85개 통과. 기존 외부 자동완성 58개와 저장·자동 로그인 관련 27개. |
| 전체 `npm test` | 183/183 통과. |
| `npm run check` | 두 userscript 문법 검사 통과. |
| `git diff --check` | 공백 오류 없음. |
| 문서 로컬 링크 | 10개 대상 파일 존재 확인. |
| 설치 링크 | 배포된 userscript와 로컬 소스의 바이트 일치 확인. |
| 실제 자격증명 | 사용하지 않음. `.test` 가상 계정만 사용. |
| 실제 계정 E2E | 미실행. Tampermonkey 등록 → 자동 입력 → MFA → 포털 진입은 최초 설치 후 확인 필요. |

이전 암호화 테스트는 제거된 기능에 대한 테스트이므로 새 저장 계약 테스트로 교체했다. 새 페이지에서 추가 입력창 없이 자동 로그인하는지, GM 이외 Web Storage로 ID/PW를 복사하지 않는지 검증했다. 이전 암호문이 유지된 경우의 차단, 새 값 저장·이전 값 삭제 실패, 설정 취소·화면 이탈, 잘못된 계정, 수동 Login·Enter도 검증했다.

## 버전 이력

- `0.1.0`: 외부 암호 관리자 자동완성을 원문 접근 없이 진행.
- `0.2.0`: 암호화 GM 저장·사용자 잠금 암호 방식. `6f4c986`, `190043d`로 발행.
- `0.3.0`: 사용자의 잠금 제거 요청에 따라 평문 GM 저장과 자동 로그인으로 변경. 보안 질문에는 저장 데이터 유출 시 ID/PW가 노출된다고 설명하고 공식 Storage 문서를 확인했다.

기존 `$gcpr` 요청에 따라 검증된 작업 단위마다 명시적 파일 staging과 일반 push를 수행한다. 기존 커밋을 재작성하거나 다른 userscript를 변경하지 않는다. 브라우저 설치·동기화 설정은 변경하지 않았으며 실제 로그인은 수행하지 않았다.
